## 1. `jwt.ParseSigned` grew a required algorithm allow-list

v4 will not parse a JWS until the caller says which `alg` values it accepts.
Every call site had to be given a list, and the correct list differs per site.

`skymarshal/token/access_token.go`:

```go
// RSA256 is the alg that Dex uses. They don't export this from any package.
// I had to look through their code to figure out which alg they were using.
token, err := jwt.ParseSigned(idToken, []jose.SignatureAlgorithm{jose.RS256})
```

This is the only decision in the whole PR that could not be made from inside
this repository. `claimsParserNoVerify` parses ID tokens minted by
`github.com/concourse/dex`; Dex signs with RS256 but exposes no exported
constant for it, so the author read Dex's source to establish the value. There
is no test in this repository that would have caught a wrong choice — see
"What the tests do and do not prove" below.

`atc/creds/idtoken/token_generator_test.go` (8 sites) and
`atc/creds/idtoken/idtoken_test.go` (1 site) pass `idtoken.DefaultAlgorithm`,
which already existed at the pre-state (`token_generator.go`,
`DefaultAlgorithm = jose.RS256`); one site that configures a non-default
generator passes `tokenGenerator.Algorithm` instead.

`testflight/idtoken_test.go` gained an import of
`github.com/concourse/concourse/atc/creds/idtoken` so that the default-token
assertion can use `idtoken.DefaultAlgorithm`, and the custom-token assertion
uses `jose.ES256` — matching the `ES256` the pipeline fixture configures. This
is the commit the PR author labelled "make testflight test for idtoken
stricter".

## 2. `jwt.Builder.CompactSerialize` → `Serialize`

`atc/creds/idtoken/token_generator.go`:

```go
-signed, err := jwt.Signed(signer).Claims(claims).Claims(customClaims).CompactSerialize()
+signed, err := jwt.Signed(signer).Claims(claims).Claims(customClaims).Serialize()
```

v4 renamed the compact serializer to `Serialize` (and `FullSerialize` remains
the JSON form). The wire format is unchanged.

## 3. A dead test helper was deleted rather than fixed

`skymarshal/token/token_suite_test.go` carried an unreferenced `parse()` helper
whose only reason to exist was the old one-argument `jwt.ParseSigned`. It was
removed along with its now-unused `time` import (`rsa` stayed — it is used by
the rest of the suite). Fixing it up to the new signature would have compiled
equally well; the author noticed it was unreachable and deleted it.

## 4. `go.mod`

`github.com/go-jose/go-jose/v3 v3.0.4` dropped from the direct require block.
`go mod tidy` additionally collapsed `go 1.24.2` + `toolchain go1.25.0` into
`go 1.25.0` and dropped `github.com/golang/protobuf` and
`github.com/google/gofuzz` from the indirect block. `github.com/go-jose/go-jose/v4
v4.1.2` was already a direct requirement at the pre-state even though nothing
imported it, so the target version was not a choice the author had to make.

## What the tests do and do not prove

Measured on the extracted trees (see `notes.md#validation`):

- A naive `sed s|go-jose/v3|go-jose/v4|` plus the `go.mod` deletion **does not
  compile**. It fails in exactly two places — `jwt.ParseSigned` arity in
  `skymarshal/token/access_token.go`, `testflight/idtoken_test.go`,
  `atc/creds/idtoken/*_test.go` and `skymarshal/token/token_suite_test.go`; and
  `CompactSerialize` in `atc/creds/idtoken/token_generator.go`. So the compile
  gate is a genuine, non-trivial discriminator.
- Substituting the **wrong** algorithm in `skymarshal/token/access_token.go`
  (`jose.ES256` for `jose.RS256`) still compiles **and still passes
  `go test ./skymarshal/token/`** — `claimsParserNoVerify` is never exercised
  directly; the suite drives a counterfeiter fake of the `ClaimsParser`
  interface. The Dex algorithm choice is therefore unguarded by any test in this
  repository. It is guarded only by production traffic, and it is the single
  place where this task rewards understanding over mechanics.
- `testflight/idtoken_test.go` is the behavioural guard for the *other* two
  algorithm choices, and it needs a live Concourse; it can only be compiled
  here.
