# A harvest that fails early disappears from the ticket step DAG

**Surface:** ticket page → "attempts" section (the per-attempt horizontal chain of
step boxes added by S-1).

## What I see

Ticket page for a run that failed in its harvest step. The attempt row renders:

```
attempt 1  [Failed]  build 562104                        $0.41
ticket → implement
```

...and that is the whole chain. There is no box for the harvest step at all, even
though the harvest step is exactly the thing that failed. The attempt header badge
is red and the run-rows table below it lists the harvest row with
`status=failed · "no-op: the workspace HEAD equals the base commit 1f3c9a2 — the
agent committed no work into the workspace checkout, so there is nothing to push.
… Nothing was pushed."`

So the DAG is telling me the attempt failed but showing me only steps that
succeeded. You have to scroll to the run-rows table to find out that a harvest
even ran. That is the opposite of what the DAG is for — it is supposed to be the
one place you can look and see where the attempt died.

## When it happens

Every harvest whose failure summary is one of these:

- `no-op: the workspace HEAD equals the base commit <sha> …`
- `workspace-dirty: uncommitted changes present (F33) …`
- `workspace is not a git repository — the agent must commit its work into the
  workspace checkout`
- `judge config invalid: …`

Harvests that get further render fine. A harvest that ran its gates shows the
expected chain and I have no complaints about it:

```
ticket → implement → gate: build → gate: test → judge 8/10 → push
```

so whatever this is, it is specific to the early-failure harvests.

## What I expect

A step that ran shows up in the attempt chain, and a step that failed reads as
failed (same status colors as everywhere else). I should be able to see "the
harvest is the red thing" without leaving the chain. Whatever renders should be
a single box named for the step it stands for — `harvest` — the way the other
boxes in the chain are named for theirs.

## Constraints

- Do not change how a harvest that got all the way through renders. The long
  chain in the example above is the S-1 headline and it is covered by tests —
  keep it exactly as it is, including labels, ordering and colors.
- Colors come from the shared agent status palette; a box in the chain should
  get its status the same way the rest of the chain gets its own.
- This should be a web-side change only. The metrics endpoint already returns
  everything the page needs; no new route, no server change, no migration.
- Scope is Elm source. The compiled bundle under `web/public/` is regenerated by
  a separate release commit for the branch, not per-change — leave it alone.
- `elm-test` from `web/elm` (or `yarn test` from the repo root) must be green,
  and please add a regression test for this.
