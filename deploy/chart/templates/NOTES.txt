{{- if and (include "concourse.agentStepConfigured" .) (not .Values.networkPolicy.hermeticEgressTo) }}

WARNING: agent: steps are configured (agentSnapshots.enabled,
--agent-step-image, or CONCOURSE_AGENT_STEP_IMAGE), and
networkPolicy.hermeticEgressTo is empty.

  Hermetic task and agent pods run under a deny-all egress NetworkPolicy
  named {{ include "concourse.fullname" . }}-hermetic-egress
  in namespace {{ include "concourse.kubernetesNamespace" . }}.

  An agent: node cannot reach a model endpoint unless agentBroker is enabled
  with agentBroker.networkPolicy.egress configured; otherwise the run fails
  with only a client-side timeout and no explanation.

  If this deployment runs agent: nodes without the broker,
  set networkPolicy.hermeticEgressTo to complete NetworkPolicy egress rules
  for your model endpoint or egress proxy (and DNS, if the endpoint is
  resolved by name — see the example in values.yaml). A deployment that runs
  only deterministic task: functions, or routes all agent traffic through
  agentBroker, can leave it empty.
{{- end }}

{{- if and .Values.alertingRules.enabled (not .Values.web.metrics.enabled) }}

WARNING: alertingRules.enabled is true but web.metrics.enabled is false.

  The concourse_k8s_*, concourse_db_* and concourse_workers_* alerts in
  {{ include "concourse.fullname" . }} read series that exist only on the web
  node's Prometheus listener, which the ATC starts only when it is given
  --prometheus-bind-ip and --prometheus-bind-port. With web.metrics.enabled
  false those flags are not rendered, no exporter publishes the series, and
  those alerts evaluate over an empty vector forever. Prometheus reports no
  error for that, so they read as healthy while the conditions they describe
  go unnoticed.

  Set web.metrics.enabled=true (and serviceMonitor.enabled=true to scrape it),
  or disable alertingRules.
{{- end }}
